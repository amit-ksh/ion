# Nebius execution options for ion agent teams

Research checked 2026-09-28 against Nebius's own documentation. This is an API and product assessment, not a live account test.

## Finding

Nebius has a **Sandboxes** product under Token Factory, branded **ConTree**, expressly intended for isolated AI-agent code execution. It is a closer fit for a task-selected cloud execution host than a manually managed Nebius Cloud VM. Nebius describes VM-level isolation, OCI base images, persisted image checkpoints, branching, rollback, asynchronous operations, file artifacts, and resource metrics. The product is marked **Beta**; its MCP quickstart also calls access **Early Access**. [Sandboxes overview](https://docs.tokenfactory.nebius.com/sandboxes/overview), [MCP quickstart](https://docs.tokenfactory.nebius.com/sandboxes/mcp/quickstart)

Nebius **model inference** is a separate boundary: Token Factory's OpenAI-compatible model API uses `https://api.tokenfactory.nebius.com/v1/`. Sandboxes use `https://api.tokenfactory.nebius.com/sandboxes`, with sandbox operations, images, files, and project-scoped auth. A working inference key must not be assumed to grant sandbox execution; verify access with the user's actual project. [Inference API example](https://docs.tokenfactory.nebius.com/api-reference/examples/batches), [Sandbox auth and URL](https://docs.tokenfactory.nebius.com/sandboxes/cli/tutorial/installation), [Sandbox REST auth](https://docs.tokenfactory.nebius.com/api-reference/sandboxes/instances/spawn-a-new-container-instance)

## Capabilities relevant to ion

| Need | Verified product surface |
| --- | --- |
| Start a task in isolation | `POST /instances` accepts at least `command` and `image`; request fields include environment, working directory, stdin, timeout, output cap, file inputs, resource limits, and networking. The REST API calls for an IAM bearer token **and** `Project` header. [Instance API](https://docs.tokenfactory.nebius.com/api-reference/sandboxes/instances/spawn-a-new-container-instance) |
| Run coding-agent tools | ConTree MCP `run` starts an isolated microVM, can run asynchronously, and returns stdout, stderr, exit status, and optionally a resulting image. The MCP reference says approximately 2–5 seconds of startup. [MCP run](https://docs.tokenfactory.nebius.com/sandboxes/mcp/tools/run) |
| Move a selected workspace | MCP `rsync` uploads selected local files with excludes and caching; subsequent runs use its `directory_state_id`. SDK can upload files and bake them into an image. This is an explicit sync, not direct access to the user's local disk. [MCP rsync](https://docs.tokenfactory.nebius.com/sandboxes/mcp/tools/rsync), [SDK files](https://docs.tokenfactory.nebius.com/sandboxes/sdk/python_sdk/running-commands) |
| Preserve/branch work | Each SDK command can produce a new image; sessions support branch and rollback. Useful for parallel alternatives, but ion should still track which branch/checkpoint owns each result. [SDK getting started](https://docs.tokenfactory.nebius.com/sandboxes/sdk/python_sdk/getting-started), [CLI sessions](https://docs.tokenfactory.nebius.com/sandboxes/cli/tutorial/sessions) |
| Monitor and cancel | Long operations expose polling/cancellation; MCP offers operation status and cancel tools. [Sandboxes overview](https://docs.tokenfactory.nebius.com/sandboxes/overview), [MCP cancel](https://docs.tokenfactory.nebius.com/sandboxes/mcp/tools/cancel_operation) |

## Setup and implementation boundary

1. The user needs a Nebius project with Sandboxes/ConTree access, a token accepted by that project, and billing/quota eligibility. Nebius's CLI docs say all ConTree calls need a bearer token and project ID; `contree auth` stores credentials in a local profile. Its MCP docs describe both a Nebius IAM profile and an older `contree.dev` JWT flow, and direct early-access applicants to a request form. **Verify the exact credential type and entitlement with the user's account before promising one-key setup.** [CLI installation/auth](https://docs.tokenfactory.nebius.com/sandboxes/cli/tutorial/installation), [MCP quickstart](https://docs.tokenfactory.nebius.com/sandboxes/mcp/quickstart)
2. ion can prototype through ConTree MCP or its Python SDK, then implement a native daemon adapter against the documented REST API if a durable product integration is desired. The Python SDK delegates credentials, URL, retries, and transport to `contree-client`; ion's Windows desktop need not install Python if the daemon speaks REST directly. This last sentence is an architectural inference from the documented surfaces, not a tested integration. [SDK getting started](https://docs.tokenfactory.nebius.com/sandboxes/sdk/python_sdk/getting-started), [Instance API](https://docs.tokenfactory.nebius.com/api-reference/sandboxes/instances/spawn-a-new-container-instance)
3. Keep task routing explicit: `user machine` for local files, apps, microphone, and computer control; `Nebius sandbox` for portable code/test/research jobs after an explicit workspace sync. Return patch/artifacts to ion and require a local review/apply step before modifying the user's checkout. This is a recommended ion design based on the documented sync and artifact model, not an existing Nebius feature. [MCP quickstart file sync](https://docs.tokenfactory.nebius.com/sandboxes/mcp/quickstart), [MCP rsync](https://docs.tokenfactory.nebius.com/sandboxes/mcp/tools/rsync)
4. Add a readiness check that lists image access and runs a trivial disposable command, then test upload/download, cancellation, checkpoint continuation, and failure recovery. Do not mark the cloud path working solely because Token Factory inference responds. [MCP quickstart](https://docs.tokenfactory.nebius.com/sandboxes/mcp/quickstart), [MCP run](https://docs.tokenfactory.nebius.com/sandboxes/mcp/tools/run)

## Limits and unresolved questions

- Beta docs specify at most **50 simultaneous running operations** and **180-day retention** for untagged, unreferenced checkpoint images. [Sandboxes overview](https://docs.tokenfactory.nebius.com/sandboxes/overview)
- The sources reviewed do not establish a Sandboxes price, a guaranteed geographic region, Windows-native guest images, or general access for every Token Factory account. Confirm these in the user's account and current agreement before exposing automatic cloud routing.
- Nebius Cloud Compute VMs and Serverless AI jobs are separate fallback products with their own provisioning and credentials; they are not required for an initial ConTree integration. [Compute VM quickstart](https://docs.nebius.com/compute/quickstart), [Serverless AI job quickstart](https://docs.nebius.com/serverless/quickstart/jobs)
