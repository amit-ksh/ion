# OpenManus research for ion

Checked 2026-09-28 against [FoundationAgents/OpenManus](https://github.com/FoundationAgents/OpenManus). This is product research, not a decision to adopt its runtime or code. The [ion product plan](README.md) remains authoritative.

## What OpenManus actually provides

- Its general agent runs a model tool loop with local Python execution, file editing, a human-question tool, and a termination tool. It can discover tools from configured MCP servers. The current source starts Browser Use CLI as a default MCP server and offers a persistent browser session through that server. [Agent source](https://github.com/FoundationAgents/OpenManus/blob/main/app/agent/manus.py), [README browser setup](https://github.com/FoundationAgents/OpenManus/blob/main/README.md#browser-automation).
- The separate `run_flow.py` path asks the model for a plan, dispatches each step to an agent based on an optional `[AGENT_NAME]` tag, and tracks `not_started`, `in_progress`, `completed`, and `blocked` states. The README itself labels this multi-agent mode **unstable**. Its plan store is a process-local dictionary, and the flow marks a step complete after an executor returns; those are limits to improve on, not durability guarantees. [Planning flow](https://github.com/FoundationAgents/OpenManus/blob/main/app/flow/planning.py), [planning tool](https://github.com/FoundationAgents/OpenManus/blob/main/app/tool/planning.py), [README](https://github.com/FoundationAgents/OpenManus/blob/main/README.md#quick-start).
- A separate data-analysis agent has Python, chart preparation, and visualization tools. MCP tool definitions are fetched on connection and made available to the model. [Data-analysis agent](https://github.com/FoundationAgents/OpenManus/blob/main/app/agent/data_analysis.py), [MCP client](https://github.com/FoundationAgents/OpenManus/blob/main/app/tool/mcp.py).

## Fit with ion today

ion already has a [native Nebius task loop](09-native-nebius-runtime.md), [sequential specialist delegation and report artifacts](10-workflows-github.md), [approval and uncertain-outcome recovery](05-agent-teams-automations.md), an [embedded browser and development-only Cua integration](../computer-use.md), and [phone/cloud daemon control](14-phone-asr-cloud-execution.md). The current specialist implementation has bounded, read-only child runs, not a persistent user-visible plan of multiple typed steps. OpenManus's broad local Python/editor tool set would expand execution authority beyond ion's current task grants.

## Architecture guardrails

Keep the daemon and task journal authoritative. A plan step needs a durable ID, policy grant, idempotency key for effects, and a recovery state for interrupted or uncertain work. Treat MCP server instructions and browser page content as untrusted input; registering a server must not automatically grant every discovered tool to every task. Keep arbitrary Python/shell execution in an explicitly selected isolated environment, with time, output, workspace, and network bounds. The OpenManus source demonstrates that its current flow and MCP discovery are useful precedents, but it does not supply ion's required durable approvals or recovery semantics. [OpenManus planning tool](https://github.com/FoundationAgents/OpenManus/blob/main/app/tool/planning.py), [OpenManus MCP client](https://github.com/FoundationAgents/OpenManus/blob/main/app/tool/mcp.py), [ion architecture](03-target-architecture.md).
