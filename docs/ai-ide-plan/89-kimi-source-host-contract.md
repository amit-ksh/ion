Checked 2026-10-16 against the **released** official commit `472192c34c1efad89a369870eff0da0b708ce9bb`, not moving main. Complements [83](83-kimi-current-contract.md). This note verifies source interfaces; it does not claim an executed host, production bridge, selected-account acceptance or support for extending an installed `kimi.exe`.

A source-built Ion host is an explicitly versioned **separate distribution using Kimi’s released native engine**. It must not be reported as a plugin loaded by the owner-selected stock executable. Preserve the ordinary installed-binary ACP path independently until the owner chooses/accepts a host route.

## Composition and registration before the first prompt

`runAcpServerWithStream(stream, opts)` returns `{core, klient, conn, close}`. It performs ordinary bootstrap, configured storage/logging, memory klient creation, ACP filesystem/terminal runtime registration and server wiring. Its `extraSeeds` replace DI services and are explicitly test-oriented: do not use them to replace production authentication, permission or model adapters. [Released composition](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/start.ts).

**Startup ordering:** the connection starts before an awaited provider registration and before the function returns. Installing authority only after awaiting this function leaves an inbound-message race. Prefer an additive, uniquely named Session-scoped `ScopeActivation.OnScopeCreated` service registered before bootstrap; it subscribes to the existing `IAgentLifecycleService.onDidCreateScope`. Alternatively, an embedding host must gate inbound ACP reads until all subscriptions are installed. Do not replace an existing scoped service to obtain the hook. [Scoped registration](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/_base/di/scope.ts).

The released main-agent identity is `MAIN_AGENT_ID = 'main'`. `onDidCreateScope` fires synchronously with `{context, handle}` after metadata registration and **before** dispatcher restore, profile bootstrap, tool activation and loop attachment. The trusted `AgentContext` carries lifecycle generation; retain that exact context, session ID and handle rather than accepting any of them in tool arguments. `ensureMainAgent` reuses the lifecycle’s existing main agent and deduplicates concurrent creation. [Lifecycle interface](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/session/agentLifecycle/agentLifecycle.ts), [creation ordering](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/session/agentLifecycle/agentLifecycleService.ts), [ensure helper](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/session/agentLifecycle/mainAgent.ts).

## Executable tools and default behavior

1. Check `registry.resolve(name)` before registering **each** of the five Ion actions. The registry replaces an existing same-name entry; collision refusal belongs in Ion. Store each returned disposable. Its removal checks the exact registration object, so disposing Ion’s old entry will not remove a later owner replacement. [Registry](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/toolRegistry/toolRegistryService.ts).
2. Register with `source: 'user'`, retain every native built-in and do not clear registry/profile configuration. A tool implements `name, description, parameters, resolveExecution(originalArgs)`; its runnable result supplies `approvalRule`, optional declared accesses, and `execute(ctx)`. `ctx` contains native numeric `turnId`, string `toolCallId` and `AbortSignal`. Return `{output, isError?:false}` for native success. [Executable contract](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/tool/toolContract.ts).
3. Add only Ion names using `profile.addActiveTool(name)` when the profile has an explicit active-tool list. Undefined means no restrictive list, so the method intentionally does nothing. This is an ephemeral overlay, emits no status event and is reset by profile bind/apply/snapshot operations. Re-add after profile updates (for example, observe `AgentStatusUpdated` with the same lifecycle context) before prompting; early registration alone is insufficient. Do not overwrite `activeToolNames` with only Ion’s names. [Profile interface](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/profile/profile.ts), [overlay implementation](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/profile/profileService.ts#L542).
4. Native executor guards still compose profile, global, session and workspace disabled-tool policies. Native before-execution approval uses the ordinary permission policy and approval service. Keep both active; the Ion worker’s owner grant/run-limit approval is an additional boundary. An observer exception is caught by the native event emitter, so any failed registration/witness must explicitly leave Ion tools unavailable. [Tool policy](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/toolPolicy/toolPolicyService.ts), [permission gate](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/permissionGate/permissionGateService.ts), [event delivery](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/_base/event.ts).

## Independent call witness and cancellation

The native executor parses/validates original arguments, resolves the executable, awaits native before-execution decisions, awaits will-execute work, dispatches `ToolCallStarted`, then invokes the executable. The event contains `agentId, turnId, toolCallId, name, args`. On the normal non-reentrant path, dispatcher publication and synchronous event listeners run before the executable starts; the callback must nevertheless refuse if its independent witness is missing. Observe using `ISessionEventBus.onAgent(exactContext, ToolCallStarted, listener)`, and verify `sourceOf(event)`/lifecycle generation. [Executor](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/toolExecutor/toolExecutorService.ts), [event fields](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/toolExecutor/toolExecutorEvents.ts), [bus](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/app/event/eventBus.ts), [dispatcher](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/state/eventDispatcherService.ts).

Compare exact canonical arguments, name, native call/turn IDs and captured session/context before invoking the shared worker. Arguments alone, an MCP request ID, an Ion random ID or model-supplied metadata do not establish this identity. The event is observable but is also emitted for denied/synthetic/preflight-error outcomes; **an event by itself never authorizes work**. Require the actual executable callback and both native/Ion approval boundaries. Identical arguments under different native calls remain distinct.

Native execution races callback completion against a **two-second abort grace**. An uncooperative callback can still run after the engine has reported cancellation: Ion must listen to the signal immediately, revoke worker authority and suppress late results. Recheck active turn/generation immediately before dispatching work. Do not interpret the engine’s settled error as proof that the callback stopped. [Abort grace and result finalization](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/agent/toolExecutor/toolExecutorService.ts).

On agent `onWillClose`, revoke authority before awaiting cleanup; dispose registrations/subscriptions on `onDidClose` and host close. Agent removal cancels queued/in-flight prompts, waits up to three seconds for quiescence, stops tasks and disposes the scope. ACP `session/close` tears down its session and underlying lifecycle; load/resume re-materialize stored scopes and wire the current main agent. Use a per-context registration map so same-live-session resume is idempotent, and a new generation never inherits old callback permission. [Removal](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/session/agentLifecycle/agentLifecycleService.ts), [ACP lifecycle](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/server.ts), [host drain order](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/start.ts).

## Account/configuration and real HTTP fixture

Production must forward the selected Kimi home/config/environment and retain native model resolution, OAuth/static/provider credentials and ordinary permission mode. The stock CLI passes `homeDir: getDataDir()`, agent identity/version, `KIMI_CODE_HOME` in terminal-auth env, and its executable as legacy terminal-auth command. A custom host must deliberately preserve/reproduce login routing; advertising its own unsupported `--login` is not compatibility. The ACP auth gate accepts the default model’s config/env/OAuth readiness before its OAuth-summary fallback. Leave `disableAuth` false/omitted. [Stock CLI wiring](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/apps/kimi-code/src/cli/sub/acp.ts), [home precedence](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/agent-core-v2/src/app/bootstrap/bootstrap.ts), [auth gate](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/server.ts#L625).

The upstream [fake-model configuration helper](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/test/_helpers/fakeModelConfig.ts) supplies the exact native TOML shape:

```toml
defaultModel = "ion-fixture"
[models.ion-fixture]
name = "ion-fixture-model"
protocol = "openai"
baseUrl = "http://127.0.0.1:PORT/v1"
apiKey = "disposable-fixture-token"
maxContextSize = 8192
```

Write it only to a disposable home **before** bootstrap; bind a localhost HTTP OpenAI-compatible streaming server and use the native protocol adapter without `extraSeeds`. The upstream [ACP end-to-end tests](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/test/e2e-turn.test.ts) use a scripted registry override, so their flow/helpers are useful scaffolding but do not prove real HTTP/auth preservation. No such real-HTTP ACP fixture was identified in the inspected released ACP tests.

## Next implementation gates

- [ ] Reproducible isolated source-host artifact and verified default native dependencies/tools.
- [ ] Early additive lifecycle registration, collision refusal, profile-refresh activation and scoped event witness.
- [ ] Real localhost-provider call → normal native approval → Ion grant approval → successful native result on the same call.
- [ ] Identical-call separation; missing/foreign/changed bindings; changed team definitions; native denial; Stop during both approvals and execution; stale callbacks; clean EOF/disposal and resume.
- [ ] Explicit packaging/selection/login compatibility and selected-account/platform acceptance.

The APIs provide a concrete implementation seam. Source-built artifact execution, real native callback acceptance and owner-selected host compatibility remain unproven gates, rather than an assertion that stock Kimi has an external tool-registration extension.
