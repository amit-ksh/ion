Waku, extended directly

AI work, in motion.

A local-first AI work IDE built on Waku’s daemon and native clients—adding durable tasks, specialist agent teams, connected apps, automations, PR/Issue workflows, voice, and secure remote decisions.

Product name · ion Primary track · Coding & Agentic Engineering Deadline · Oct 30, 2026 · 10:00 AM PDT Status · architecture frozen for planning

01 · Decisions

The shape of the product

Keep Waku’s strongest boundary—the local daemon—and add an explicit cloud control plane only where availability, integrations, identity, or managed compute require it.

01

Tasks over chats

Project → Task → Run becomes the durable product model. Chat remains one surface.

02

Hybrid by design

Code and terminals stay local by default; Nebius adds models, isolation, and finite jobs.

03

Authority stays human

Models propose. Waku policy authorizes. Consequential external writes need approval.

04

Mobile is control

The phone reviews, steers, approves, and stops work running on desktop or cloud.

02 · Evidence

System views stay stable

PRs, Issues, Automations, Apps, and Teams are first-class domain views—not special chat titles.

Pinning is explicit

Projects and tasks may be shortcuts in Pinned. Pinning never changes permissions or execution location.

The daemon resolves collections in the background; the native sidebar reads an in-memory projection and stays virtualized.

07 · Mobile

Remote control is feasible now—with limits

The repository already contains iOS and Android clients for remote daemon tasks. Production access still needs a relay, scoped pairing, revocation, replayable events, and push.

YES

Use the phone as a control plane

Start, queue, steer, review files/diffs, use a remote terminal, approve, cancel, and stop work on a reachable Waku host.

Must feel complete

  • One working team and one GitHub workflow
  • One visibly isolated Nebius execution
  • One voice request and one inspectable automation
  • One mobile review/approval moment

Do not build for the hackathon

  • Payments or entitlements
  • Arbitrary recursive organization graphs
  • Unattended main-desktop control
  • Native phone agents or broad internal rename
